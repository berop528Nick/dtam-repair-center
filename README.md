# ระบบแจ้งปัญหาคอมพิวเตอร์และอุปกรณ์ (IT Service Desk · Google Apps Script)

เว็บแจ้งปัญหาคอมพิวเตอร์/อุปกรณ์ (แจ้งซ่อม แจ้งเสีย เครื่องปริ้น ฯลฯ) ภาษาไทย
ผู้แจ้งไม่ต้องล็อกอิน — บันทึกข้อมูลลง Google Sheet ออกเลขที่ใบแจ้ง
(`RQ` + ปีเดือน + รหัสสุ่ม เช่น `RQ2611-X7K9P2` เดาไม่ได้) และแจ้งเตือนผู้ดูแลทางอีเมล/LINE

## ดีพลอยด้วย clasp (แนะนำ)

```bash
npm install -g @google/clasp
clasp login
clasp push                       # อัปโหลดเฉพาะไฟล์ใน .claspignore
clasp deploy -d "v1"             # สร้าง deployment ใหม่ (ได้ URL ใหม่)
```

ถ้าต้องการอัปเดต deployment เดิม (URL เดิมไม่เปลี่ยน) ให้ดูรหัส deployment แล้วระบุ `-i`

```bash
clasp deployments
clasp deploy -i YOUR_DEPLOYMENT_ID -d "v2"
```

> ทุกครั้งที่แก้โค้ด ต้อง `clasp push` แล้ว deploy เวอร์ชันใหม่เสมอ
> ถ้าไม่ทำ URL เดิมจะยังรันโค้ดเก่า
>
> ถ้าเพิ่มไฟล์ HTML ใหม่ ต้องเพิ่มชื่อไฟล์ใน `.claspignore` ด้วย ไม่งั้นจะไม่ถูกอัปโหลด
> ถ้าโปรเจกต์บน Apps Script ยังมีไฟล์เก่าอย่าง `Index.html` ค้างจาก `clasp push` ครั้งก่อน
> ให้ลบไฟล์นั้นในหน้า editor หนึ่งครั้ง (`.claspignore` คุมการอัปโหลด แต่ไม่ลบไฟล์บนเซิร์ฟเวอร์)

## ดีพลอยจากหน้าเว็บ (ไม่ต้องใช้เครื่องมืออื่น)

1. เปิดโปรเจกต์: https://script.google.com/home/projects/1FBzzbDvFCCKM3rnfPyTesCoEbOxDk-uwib2CQZM2hmLQZbcF42IyJ62K/edit
2. วางเนื้อหา `Code.gs` ทั้งไฟล์ลงในไฟล์ `Code.gs`
3. เปิด `Project Settings` > ติ๊ก **Show "appsscript.json" manifest file in editor** แล้ววางเนื้อหา `appsscript.json`
4. กด `+` > HTML สร้างไฟล์ชื่อตรงกับตารางด้านบนให้ครบ 12 ไฟล์
   (`Repair`, `Track`, `Login`, `Dashboard`, `Equipment`, `Brand`, `PubHead`, `Shell`, `Styles`, `AppJS`, `NavJS`, `Dialog`)
   แล้ววางเนื้อหาของแต่ละไฟล์ตามชื่อ — ชื่อไฟล์ต้องตรงตัวพิมพ์เล็ก/ใหญ่ เพราะ `include()` อ้างตามชื่อ
5. ตั้งค่าใน `CONFIG` (ต้นไฟล์ `Code.gs`)
   - `SPREADSHEET_ID` — ถ้าไม่ผูกสคริปต์กับชีต ให้สร้างชีตใหม่แล้วเอาไอดีจาก URL มาใส่
     (ถ้าเว้นว่าง สคริปต์จะใช้ชีตที่ผูกอยู่ และสร้างชีตชื่อ `แจ้งซ่อม` ให้อัตโนมัติ)
   - `ADMIN_EMAILS` — อีเมลผู้ดูแล เช่น `['admin@school.ac.th']` (เว้นว่าง = ไม่ส่งอีเมล)
   - `LINE_CHANNEL_TOKEN` / `LINE_USER_ID` — ถ้าต้องการแจ้งเตือนผ่าน LINE Messaging API
6. รันฟังก์ชัน `testSetup` หนึ่งครั้ง แล้วกด **Allow** เพื่อให้สิทธิ์
   (ผลลัพธ์จะบอกว่าชีต/โฟลเดอร์/อีเมลพร้อมใช้งานหรือยัง)
7. `Deploy` > `New deployment` > เลือกชนิด **Web app**
   - Description: `v1`
   - Execute as: **Me**
   - Who has access: **Anyone** (ให้ผู้แจ้งทั่วไปเปิดได้โดยไม่ต้องล็อกอิน)
     หรือ **Anyone with Google account** ถ้าต้องการจำกัดเฉพาะในองค์กร
8. คัดลอก Web app URL ไปใช้งาน/แปะใน Google Sites หรือ LINE

## ขึ้น Google Sheet ใหม่ (ย้ายระบบไปชีตอื่น)

1. สร้างสเปรดชีตใหม่ (บัญชีเดียวกับเจ้าของสคริปต์) แล้วคัดลอกไอดีจาก URL
   (`https://docs.google.com/spreadsheets/d/<SPREADSHEET_ID>/edit`)
2. ใส่ไอดีใน `CONFIG.SPREADSHEET_ID` ต้นไฟล์ `Code.gs` แล้ว `clasp push`
   (หรือแก้ใน editor แล้ว Deploy เวอร์ชันใหม่)
3. หน้า editor เลือกฟังก์ชัน **`setupAll`** แล้วกด Run (ครั้งแรกกด **Allow**)
   ฟังก์ชันเดียวสร้างให้ครบ: ชีต `แจ้งซ่อม` + หัวตาราง 24 คอลัมน์, ชีต `ครุภัณฑ์`,
   ชีต `Users` (+ บัญชี `admin` ตั้งต้น), โฟลเดอร์รูปใน Drive — ผลลัพธ์อยู่ใน Execution log
4. ตั้งรหัสผ่านจริงทันที: `setUserPassword("admin", "รหัสผ่านใหม่", "ชื่อที่แสดง", "admin")`
   (ห้ามใช้ `admin/admin1234` ขึ้น production) แล้วเพิ่มเจ้าหน้าที่คนอื่นด้วยฟังก์ชันเดียวกัน
5. ถ้าต้องการข้อมูลทดสอบ: รัน `seedDemoData()` (2,000 ใบ: รอดำเนินการ 5 ใบ +
   ที่เหลือสุ่ม, ครุภัณฑ์ 8 รายการ, เบอร์โทร/ไลน์สมมติสำหรับทดสอบค้นหา)
   — ล้างด้วย `seedDemoData(true)` ก่อนเปิดใช้จริง
6. รัน `testSetup` ตรวจท้าย (ชีต/โฟลเดอร์/อีเมล/LINE) แล้ว Deploy เวอร์ชันใหม่

> เลขที่ใบแจ้งเป็นรหัสสุ่ม ตรวจซ้ำกับเลขเดิมในชีตให้อัตโนมัติ — ย้ายชีตใหม่ก็ใช้ได้เลยไม่ต้องนับต่อ
> ถ้าชีตปลายทางมีข้อมูล/หัวตารางเดิมที่ไม่ตรง สคริปต์จะหยุดพร้อมข้อความบอก
> ให้เปลี่ยนชื่อชีตหรือล้างแถวแรกก่อน (กันข้อมูลเพี้ยนแบบเงียบ ๆ)

## ปรับปรุงหน้าเว็บในเครื่อง (โฟลเดอร์ `preview/`)

ใช้ `preview/` เป็นชุดทำงานสำหรับออกแบบ/ปรับปรุงหน้าเว็บ แล้วค่อยแปลงกลับเป็น Apps Script เมื่อพอใจ

```bash
node tools/preview.mjs           # สร้างครั้งแรก
node tools/preview.mjs --force   # สร้างใหม่จาก template (ลบของเดิมทั้งหมด)
```

| ไฟล์ใน `preview/` | ใช้แก้ |
| --- | --- |
| `form.html` | ฟอร์มแจ้งปัญหา |
| `track.html` | ติดตามสถานะ |
| `login.html` | เข้าสู่ระบบ |
| `dashboard.html` | หน้าแรก / ประวัติ |
| `equipment.html` | รายละเอียดครุภัณฑ์ |
| `assets/styles.css` | CSS กลางทั้งระบบ (สี ฟอนต์ เลย์เอาต์) — จาก `Styles.html` |
| `assets/app.js` | JS กลาง (กล่องแจ้งเตือน เมนู ตาราง) — จาก `AppJS.html` |

- เปิด `preview/form.html` ใน Chrome ได้เลย เมนูนำทางระหว่างหน้าได้
- แก้ไฟล์ใน `preview/` ได้โดยตรง สคริปต์จะ **ไม่เขียนทับ** ถ้าไม่ใส่ `--force`
- หน้า preview ยังใช้ข้อมูลตัวอย่าง (`ROWS`, `TICKETS`) และฟอร์มยังไม่บันทึกจริง
- ทุกครั้งที่ build จะเติมเลขรุ่นท้ายไฟล์ (`assets/styles.css?v=...`, `assets/app.js?v=...`)
  เพื่อไม่ให้เบราว์เซอร์ใช้ CSS/JS เก่าจาก cache — ถ้าแก้แล้วไม่เห็นผล ให้กด **Ctrl + Shift + R**
  หรือ build ใหม่

> อย่ารัน `--force` หลังแก้ใน `preview/` เพราะจะลบงานที่แก้ทั้งหมด
>
> `--force` ลบเฉพาะ **เนื้อหา** ใน `preview/` ไม่ลบตัวโฟลเดอร์ จึง build ได้แม้เปิด
> Live Server (VS Code) หรือเซิร์ฟเวอร์พรีวิวค้างอยู่ — ก่อนหน้านี้ลบทั้งโฟลเดอร์แล้วโดน EPERM
> ทำให้ build ล้มเงียบ ๆ และไฟล์ใน preview เป็นของเก่า

เมื่อออกแบบพอใจแล้ว บอกผมเพื่อ port กลับเข้าไฟล์ที่ deploy จริง:

- `preview/assets/styles.css` → `Styles.html` (ห่อด้วย `<style>`)
- `preview/assets/app.js` → `AppJS.html` (ห่อด้วย `<script>`)
- `preview/<หน้า>.html` → `Repair.html` / `Track.html` / `Login.html` / `Dashboard.html` / `Equipment.html`
  (คง `include()` และ scriptlet ของ Apps Script ไว้)

> ข้อมูลในหน้าเป็นตัวอย่าง (`ROWS`, `TICKETS`) และส่วนที่เรียก `google.script.run` จะไม่ทำงานในเครื่อง
> ต้องดีพลอยขึ้น Apps Script เพื่อทดสอบการบันทึกข้อมูลจริง — โฟลเดอร์ `preview/` ไม่ถูกอัปโหลดขึ้น Apps Script

## ลูกเล่น/แอนิเมชันในหน้าเว็บ

รายละเอียดที่ตั้งใจใส่ไว้ (แก้ที่ `Styles.html` เป็นหลัก)

- **สถานะกำลังโหลดหน้า** — แถบโหลดสีเขียวบนขอบจอ + ตัวหมุน “กำลังโหลด…” กลางพื้นที่เนื้อหา
  เนื้อหาจะถูกซ่อนไว้อย่างน้อย 0.43 วิ (`MIN_MS` ใน `PubHead.html` / `Shell.html`) แล้วค่อยจางขึ้น
  หัวเว็บ/เมนูข้างยังอยู่ตลอด ไม่กระพริบ — มีตัวกันเหนียวโชว์เนื้อหาภายใน 4 วิถ้าโหลดค้าง
- **เปลี่ยนหน้าอย่างนุ่มนวล** — ไม่จางหน้าที่กำลังจะออก (ซึ่งเคยทำให้จอขาวค้าง) ปล่อยให้เบราว์เซอร์
  เปลี่ยนหน้าทันที แล้วค่อยจางเนื้อหาใหม่ขึ้นจาก `opacity 0.5` เป็น 1
- **ปุ่ม “เจ้าหน้าที่เข้าสู่ระบบ”** — ตอนกด: ปุ่มจางหายก่อน 0.18 วิ แล้วค่อยไปหน้า login;
  ตอนกลับมา: ปุ่ม+เส้นคั่นกางออกพร้อมจางขึ้น ทำให้เมนู “แจ้งปัญหา / ติดตามสถานะ”
  **ไหล** เข้า/ออกจากพื้นที่ว่างอย่างต่อเนื่อง (วัดระยะจริงจาก DOM ไม่ใช้ค่าคงที่)
- **ไม่มีหน้าจอขยับจาก scrollbar** — `scrollbar-gutter: stable` ที่ `<html>` ทำให้ทุกหน้า
  กว้างเท่ากัน แถบเมนูจึงไม่เลื่อนซ้าย-ขวาเวลาเปลี่ยนหน้า
- **hover** — ช่องกรอก/ปุ่ม/ช่องอัปโหลด/ตัวเลือกช่องทางติดต่อกลับ มีขอบเขียว + ออร่าเมื่อเอาเมาส์ผ่าน
  (ไม่ต้องคลิกก่อน) และ label เปลี่ยนสีเมื่อ hover/โฟกัส
- **ปฏิทินไทย (พ.ศ.)** — ช่องวันที่ในหน้าแจ้งปัญหา / ติดตามสถานะ / ครุภัณฑ์ ใช้ตัวเลือกวันที่ตัวเดียวกัน
  แสดงปี พ.ศ. และปฏิทินเปลี่ยนเดือนได้
- **ตารางหน้าแรก** — ค้นหา/เรียง/เปลี่ยนหน้าแบบมีแอนิเมชัน, ปุ่มแบ่งหน้าย่อเลขหน้า
  (`1 … 5 6 7 … 20`) และเปลี่ยนสถานะปุ่มอย่างนุ่มนวล

## คอลัมน์ในชีต

`เลขที่ใบแจ้ง | วันเวลาที่แจ้ง | ชื่อผู้แจ้ง | หน่วยงาน | เบอร์โทร | อีเมล | ครุภัณฑ์/อุปกรณ์ | รหัสครุภัณฑ์ | หมวดหมู่ | สถานที่ | อาการเสีย/รายละเอียด | ความเร่งด่วน | รูปภาพ | สถานะ | ผู้รับผิดชอบ | หมายเหตุ`

คอลัมน์ `สถานะ` ถูกตั้งเป็น `รอดำเนินการ` อัตโนมัติ ส่วน `ผู้รับผิดชอบ` และ `หมายเหตุ`
ให้เจ้าหน้าที่กรอกเอง (แก้ในชีตได้เลย)

## ปรับแต่งที่พบบ่อย

- **เพิ่ม/แก้ตัวเลือกหน่วยงานหรือหมวดหมู่** — แก้ที่ `LISTS` ใน `Code.gs` (หน้าเว็บอ่านจากที่นี่)
- **ขนาดไฟล์แนบ** — `CONFIG.MAX_FILE_MB` (ค่าเริ่มต้น 5 MB) และโฟลเดอร์ปลายทาง `DRIVE_FOLDER_NAME`
- **รูปแบบเลขที่ใบแจ้ง** — แก้ในฟังก์ชัน `nextTicketNo_` (ค่าเริ่มต้นรายเดือน)
- **เปลี่ยนโลโก้หัวเว็บ** — Apps Script แสดงไฟล์รูปในโปรเจกต์โดยตรงไม่ได้ จึงฝังเป็น base64
  ใน `Brand.html` และ `PubHead.html` วิธีเปลี่ยน: เตรียมรูปทรงกลมพื้นหลังขาว (ต้นฉบับอยู่ใน `assets/`)
  แปลงเป็น base64 แล้วแทนค่าใน `src` หรือใช้ Python:
  `python -c "import base64,pathlib;print(base64.b64encode(pathlib.Path('assets/logo-dtam-seal.png').read_bytes()).decode())"`
  แล้วนำผลไปต่อท้าย `data:image/png;base64,`
- **สีของธีม** — ปรับที่ตัวแปร CSS ใน `:root` ของ `Styles.html` ที่เดียว
- **ไม่ต้องการแนบรูป** — ลบช่องอัปโหลดทั้ง 3 ช่องใน `Repair.html` ฝั่ง backend จะไม่บันทึกรูปถ้าไม่มีไฟล์ส่งมา

## หน้าเว็บและเส้นทาง (URL)

หลัง deploy จะได้ URL เดียว เช่น `https://script.google.com/macros/s/xxxx/exec`
แล้วเลือกหน้าด้วย `?page=`

| URL | หน้า | ไฟล์เทมเพลต |
| --- | --- | --- |
| `/exec` หรือ `/exec?page=form` | **ฟอร์มแจ้งปัญหา (สาธารณะ ไม่ต้องล็อกอิน)** | `Repair.html` |
| `/exec?page=track` | **ติดตามสถานะด้วยเลขที่ใบแจ้ง (สาธารณะ)** | `Track.html` |
| `/exec?page=login` | เข้าสู่ระบบ (เฉพาะแอดมิน/เจ้าหน้าที่) | `Login.html` |
| `/exec?page=dashboard` | ภาพรวมการแจ้งปัญหาทั้งหมด | `Dashboard.html` |
| `/exec?page=dashboard&scope=mine` | งานของฉัน (กรองตามผู้รับผิดชอบที่ล็อกอิน) | `Dashboard.html` |
| `/exec?page=equipment` | รายละเอียดครุภัณฑ์ | `Equipment.html` |

> `/exec` เปิดฟอร์มแจ้งปัญหาทันที — ใครมีลิงก์ก็แจ้งปัญหาได้โดยไม่ต้องล็อกอิน
> ส่วนหน้าเข้าสู่ระบบใช้ลิงก์ “เจ้าหน้าที่เข้าสู่ระบบ” มุมขวาบนของฟอร์ม หรือเข้า `/exec?page=login`
> โดยตรง (ผู้ใช้ทั่วไปไม่เห็นเมนูของแอดมิน)

ลิงก์ในเมนูใช้ `?page=...` แบบ relative จึงไม่ต้องแก้อะไรเวลา deploy ใหม่
(ปุ่ม "แจ้งปัญหา" ในเมนูชี้ไป `?page=form`, "ออกจากระบบ" ชี้ไป `?page=login`)

หน้าทั้งหมดใช้ CSS ร่วมจาก `Styles.html` และ JS ร่วมจาก `AppJS.html` — แก้สีที่ `:root`
ใน `Styles.html` ที่เดียว

## สถานะงาน (หน้าเว็บก่อน — backend ทีหลัง)

เสร็จแล้ว (frontend): ฟอร์มแจ้งปัญหาใหม่ (สาธารณะ) พร้อมช่องทางติดต่อกลับ (เบอร์โทร /
ไอดีไลน์ + อัปโหลด QR), หน้าติดตามสถานะด้วยเลขที่ใบแจ้ง, หน้าเข้าสู่ระบบ,
หน้าแรกพร้อมการ์ดสรุป + ตัวกรองช่วงเวลา + ตารางประวัติ + งานของฉัน, หน้ารายการครุภัณฑ์,
เมนูข้าง/นาฬิกา/กล่องแจ้งเตือน, แนบรูปได้ 3 ภาพพร้อมพรีวิว, ส่งออก CSV และพิมพ์ PDF,
ปฏิทินไทย (พ.ศ.) ที่ใช้ร่วมกัน, สถานะกำลังโหลดหน้าและแอนิเมชันเปลี่ยนหน้า (ดูหัวข้อก่อนหน้า)

ข้อมูลตัวอย่าง (`buildTestRows()`, `DEMO_ROWS`, `DEMO_TICKETS`) ใช้เฉพาะโหมด preview
ไม่มีเซิร์ฟเวอร์ — บน Apps Script ทุกหน้าอ่าน/เขียนข้อมูลจริงกับ Google Sheet ผ่าน `google.script.run`
(`submitForm`, `getTicket`, `getTickets`, `getEquipmentItems`, `updateTicket`)

หน้า **งานของฉัน** (`?page=dashboard&scope=mine`) กรองตามชื่อผู้รับผิดชอบให้ตรงกับผู้ที่ล็อกอิน

ยังไม่ทำ: แยกสิทธิ์แอดมิน/เจ้าหน้าที่ตอนแก้ไขใบแจ้ง (ตอนนี้ผู้ล็อกอินทุกคนจัดการได้) — ดู `BACKLOG.md`

## หมายเหตุด้านความปลอดภัย

- **หน้าแรกเป็นฟอร์มสาธารณะ** (ไม่ต้องล็อกอิน) แต่ `?page=dashboard` และ `?page=equipment` ยังไม่มีการ
  ป้องกันสิทธิ์ — ใครรู้ URL ก็เปิดได้ ควรทำระบบล็อกอิน/ตรวจสิทธิ์ก่อนเปิดใช้งานจริง
- ฟอร์มเปิดให้บุคคลทั่วไปส่งข้อมูลได้ จึงควรตรวจสอบข้อมูลก่อนนำไปใช้ และไม่ควรแสดงข้อมูลในชีตต่อสาธารณะ
- รูปที่อัปโหลดถูกตั้งสิทธิ์เป็น "ใครมีลิงก์ก็ดูได้" เพื่อให้เปิดดูจากลิงก์ในชีต/อีเมลได้
  ถ้าไม่ต้องการ ให้แก้บรรทัด `created.setSharing(...)` ใน `saveFile_`
- LINE Notify (แบบ token ง่าย ๆ) ถูกยกเลิกบริการแล้ว จึงใช้ LINE Messaging API
  (สร้าง Channel access token และใส่ userId ของผู้รับ)
